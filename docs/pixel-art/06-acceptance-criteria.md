# 06 驗收標準

日期：2026-11-17
分成兩類：**可自動檢查**（寫成測試，由 `validate.js` 或 Vitest 執行）與**需要人工審查**（由使用者看目錄頁判斷）。

## 一、每個資產都要通過的自動檢查

| 編號 | 規則 | 檢查方式 |
|---|---|---|
| A1 | 尺寸等於資產定義的 `size` | 比對 `width`、`height` |
| A2 | 每個像素都是調色盤索引，或 0（透明） | 掃描 `pixels` |
| A3 | 沒有半透明 | PNG 只用 `tRNS` 的 0 與 255；引擎輸出沒有 alpha 值 |
| A4 | 外框完整：物件本體圖層中，每個不透明且四鄰有透明的像素，都是外框色。落影圖層不檢查 | 掃描邊界像素 |
| A5 | 外框不畫斜角 | 外框像素至少有一個上下左右鄰居是物件本體 |
| A6 | 用色數 ≤ 資產上限（角色 18、家具 10、植物 8，提案值；不含落影色） | 計算不同索引數 |
| A7 | 沒有孤立像素：本體內部不得有上下左右四鄰都不同色的單一像素（高光與眼睛等白名單除外） | 掃描，資產定義可列白名單 |
| A8 | 錨點在圖內，且錨點那一列有不透明像素 | 比對座標 |
| A9 | 決定性：同一個資產、種子、幀，兩次輸出位元組相同 | 產生兩次比對 |
| A10 | 變體確實不同：同一資產的不同變體，像素雜湊不同 | 比對雜湊 |
| A11 | 動畫每幀尺寸、錨點相同 | 比對 |
| A12 | 動畫相鄰兩幀的差異只在允許的範圍內（例：工作中只改手臂區域） | 差異像素的外接矩形 ≤ 資產定義的範圍 |
| A13 | 黃金雜湊：與 `golden.json` 相同，或 `version` 已更新 | Vitest |
| A14 | PNG 匯出：讀回後的尺寸、調色盤、像素與引擎輸出相同 | Node 測試 |
| A15 | metadata 欄位齊全：id、version、STYLE_VERSION、size、anchor、colors、hash、validation | JSON schema 式檢查 |

## 二、調色盤的自動檢查

| 編號 | 規則 |
|---|---|
| P1 | 總色數 ≤ 128 |
| P2 | 每條色階 3–4 階，亮度由暗到亮單調遞增 |
| P3 | 相鄰兩階色相差在 0–20 度之間，方向是越亮越偏暖 |
| P4 | 最亮階的飽和度低於中間階 |
| P5 | 外框色不是純黑 `#000000` |

P3、P4 的數字來自 Slynyrd 第 1 篇的做法，是本專案的規則，不是業界標準。

## 三、四個原型資產

| 資產 | 尺寸（提案） | 變體 | 額外的自動檢查 |
|---|---|---|---|
| 人物（坐姿） | 16×24 | 由使用者編號決定，6 個維度 | 1000 個編號產生的造型全部通過 A1–A12；`lookFor` 的結果與現行版本相同（造型穩定性）；休息時眼睛改為閉眼 |
| 木椅 | 12×16 | 木頭顏色 2 種 | 分成「椅背」與「椅面」兩層，椅背在角色之下 |
| 木桌 | 32×20 | 木頭顏色 2 種、木紋由種子決定 | 分成「桌面」與「正面」兩層，正面在角色之上；頂面佔總高 1/2–2/3 |
| 盆栽 | 12×16 | 葉形 3 種 | 葉子與花盆各自的色階 |

每個資產都要能匯出透明背景、原生大小的 PNG，以及 metadata JSON。

## 四、需要人工審查的項目

自動檢查只能證明「規則有被遵守」，不能證明「好看」。以下由使用者在目錄頁上判斷，每項給「可以／要改」，要改的寫下原因：

| 編號 | 項目 | 看哪裡 |
|---|---|---|
| H1 | 整體看起來是同一個風格 | 四個資產並排在木地板上 |
| H2 | 在 2 倍與 3 倍下都清楚，輪廓一眼可辨 | 目錄頁的 2×、3× 欄 |
| H3 | 人物看得出是「不同的人」 | 同時看 16 個隨機人物 |
| H4 | 三種狀態一眼分得出來 | 工作中、發呆、休息並排 |
| H5 | 比例協調：人坐在椅子上、桌後時看起來合理 | 組合預覽 |
| H6 | 材質看得出來：木頭像木頭、葉子像葉子 | 單一資產 3 倍 |
| H7 | 動畫自然、不吵 | 目錄頁的動畫預覽 |
| H8 | 與現有介面（羊皮紙、木板、點陣字）搭配 | 換上大廳後的截圖 |
| H9 | 沒有看起來像在模仿某個現有遊戲的角色或物件 | 全部 |

## 五、換上大廳時的驗收（第 3 階段）

自動：

- 既有後端與前端測試全部通過，斷言未修改。
- 元件仍是 `<button class="member">`，有 `aria-label`、`aria-pressed`、`data-seat`。
- 建置產物中沒有 `data:` 圖片；元件沒有 `style` 屬性、`style:`、`transition:`。
- CSS 中每個位子的位置與 `seats.js` 的錨點一致。
- 一個角色的 `<rect>` 數量 ≤ 150（提案上限），16 人場景總數 ≤ 4000。

瀏覽器（示例模式、正式產物、真實 CSP）：

- 3 倍與 2 倍下沒有模糊邊緣（放大截圖檢查）。
- 16 人滿座時沒有重疊、名牌可讀。
- 角色被桌子正面遮住下半身，點擊仍然選得到。
- 鍵盤 Tab 與 Enter 可操作。
- `securitypolicyviolation`、`error` 事件為零。
- 開啟「減少動態效果」時沒有動畫。

## 六、明確不驗收的項目

- 與 Tiny Pixel Farm 的「相似度」。目標是同等級的清晰與一致，不是相像。
- 美感的量化分數。只用上面的人工清單。
