# OpenProject 宇宙 Dashboard 設計

日期：2026-10-25
狀態：設計方向已確認，完整文件等待使用者審閱。

## 目的與範圍
建立公司 OpenProject 的唯讀宇宙 Dashboard。第一版在使用者電腦執行，預留搬到公司內網伺服器的架構。來源為 http://192.168.31.13:8080/ 。Dashboard 不修改工作項目、留言或狀態；編輯由資訊面板連結回 OpenProject 完成。

## 已確認資料模型
- 一個專案對應一個星系。
- 一個 Work package 對應一顆星球，不是每筆活動紀錄一顆星球。
- 星球以工作項目的目前 Status 區分顏色，畫面提供狀態名稱與顏色圖例。顏色依來源狀態資料建立穩定映射；來源缺少色彩時採固定調色盤，未知狀態有明確備援樣式。
- 點選星球後顯示 Subject、Author（建立者）、目前負責人、狀態、描述、更新時間與來源連結。缺漏欄位明確標記未提供。
- 參與者為建立者、目前負責人，以及可讀取活動歷史中曾留言或更新的人，依使用者 ID 去重。未指派不建立船隻；刪除或不可辨識使用者顯示可用名稱或未知使用者。
- 每個參與者是一艘繞行星球的太空船並標示名字，只有選取該星球時顯示。取消選取或切換星球，移除前一組船隻。多人時調整環繞半徑及標籤配置，面板保留完整名單。
- 所有資料以來源帳號可見範圍為限；不可讀取或不完整的歷史不可宣稱涵蓋所有參與者。

## 3D 視圖與操作
1. 預設星系總覽：各專案為有名稱標籤的星系，點選後以鏡頭過渡飛入該專案。
2. 單一星系：展示該專案的工作項目星球，點選開啟詳情與太空船。
3. 全宇宙展開：由明確切換控制展開所有可見專案及工作項目；遠方簡化細節與標籤，靠近後呈現。分批載入須顯示進度，不將部分結果當成全部。
三種視圖皆支援旋轉、平移及縮放。提供返回總覽、專案切換與重設視角。更新資料不重設鏡頭或已選項目；項目失去權限或刪除時解除選取並提示。

## 配置與外觀
深色宇宙背景、星系光暈、立體星球。上方放導覽、專案切換及全宇宙模式；右側為選取資訊；左下為狀態圖例；底部放操作提示、重設視角與更新控制。色彩之外仍用文字表達狀態。畫面以桌面瀏覽器為第一版目標。無 WebGL 時明確告知不支援，而不是空白畫面。
已認可的靜態配置草圖：`.superpowers/brainstorm/universe-design/content/layout-v1.html`。草圖為示例資料，不表示實際 API 驗證完成；草圖目錄不納入 Git。

## 架構與責任
- 前端視覺層：渲染場景、鏡頭與互動，不持有來源登入機密。
- 前端資料層：透過本機後端取得統一資料模型，管理更新、選取與載入狀態；不依賴來源 API 原始結構。
- 後端來源介接層：封裝 OpenProject 驗證、分頁、工作項目與活動讀取，僅用於讀取來源資料。
- 後端彙整與快取層：整理專案、星球、狀態及參與者，限制同時請求數，快取活動結果，避免每次更新讀取所有項目的完整歷史。
- 設定層：讀取本機私有 config。連線設定、驗證及快取邊界集中管理，使未來換部署環境不必重寫場景。
具體套件與版本於實作計畫決定，不在本次設計中假設已安裝的框架。

## 資料流程與更新
先讀取專案和工作項目，依來源分頁完整載入；選取星球才載入該工作項目活動歷史並彙整參與者。參與者載入時仍可查看已知欄位。活動需讀完所有可用分頁；失敗時顯示未完整載入。
每 60 秒自動更新，另有手動重新整理。同一輪尚未結束時不重疊請求。活動快取於來源項目更新或使用者重新整理時失效，選取中的星球隨之刷新。ID 決定穩定空間位置，避免定時更新讓星球任意跳動。
初始失敗顯示可重試錯誤；已有成功資料時保留舊資料並顯示最後成功時間及過期狀態。區分連線失敗、驗證失敗、權限不足、空專案與部分資料失敗。遇限流或暫時錯誤使用有上限的重試與退避。

## 機密與部署
本機 config 規劃為 `config/local.json`，包含必要連線及驗證資訊，排除 Git；僅提交無機密的範例設定。密碼、token、session 不寫入前端、日誌、設計文件、handoff 或測試快照。使用者已提供帳密，但目前尚未建立機密 config，不以聊天內容已存在推定檔案已儲存。
第一版服務只監聽 loopback。未來內網版沿用前後端架構，另行加入 Dashboard 使用者驗證、OpenProject 權限對應與依身分隔離的快取；不得直接把個人帳號可見資料分享給全部同事。內網正式部署不在第一版實作範圍。

## 來源驗證現況與實作前置條件
2026-10-25 以本機工具讀取來源 `/api/v3`，遭執行環境通訊端權限拒絕，未取得 HTTP 回應；此結果不能判定來源離線或帳密錯誤，且尚未嘗試登入。
官方文件說明 API 可透過 API token 驗證，網站帳密不可直接假設適用於 API。實作前須透過允許的連線方式確認公司版本、可用驗證流程及讀取欄位；優先使用 API token。需要新增 token 時另與使用者確認，不擅自建立憑證。未完成真實連線驗證前，模擬資料必須標示，不可宣稱串接完成。

## 驗收與驗證
- 三種視圖均可旋轉、平移、縮放、重設視角，總覽與單一星系可往返。
- 專案及工作項目對應正確，狀態圖例與星球顏色一致。
- 點選顯示正確詳情與來源連結；太空船包含已定義的參與者並以 ID 去重，未選取時隱藏。
- 分頁、空資料、未指派、重複名字但不同 ID、未知狀態與歷史讀取失敗均有可驗證行為。
- 自動及手動更新保留鏡頭及選取，失敗時正確保留舊資料與錯誤時間資訊。
- 使用代表性模擬資料檢查大量項目時的漸進載入與遠近細節；正式效能數值需依實際資料規模及使用者硬體量測，不預先承諾未測數字。
- 檢查前端輸出、Git 追蹤清單與日誌不包含機密，確認私有 config 被忽略。
- 以真實來源執行唯讀整合驗證，核對至少一個專案、工作項目及參與者；環境受阻則明確記錄未完成，不以模擬測試替代成功聲明。
