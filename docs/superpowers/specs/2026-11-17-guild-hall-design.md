# 公會大廳：成員當日狀態檢視設計

日期：2026-11-17
狀態：設計已經使用者同意，待審閱本文件
前置：`2026-11-16-quest-board-time-tracking-design.md`（第一階段任務布告欄，已完成）

## 1. 目標

在現有的「冒險者工時公會」加上第二個頁籤「公會大廳」：一個像素風的大廳場景，裡面坐著使用者挑選的成員。一眼看出每位成員當天是工作中、發呆還是休息；點成員可以看他當天記了哪些工時。

第二階段範圍：

- 頁籤：現有功能搬到「任務欄」頁籤，新增「公會大廳」頁籤。
- 大廳場景：吧檯、工作桌、沙發，共 16 個位子。
- 成員管理：以名稱搜尋 OpenProject 使用者後加入；可移除。最多 16 位。
- 成員狀態：依當日工時判定為休息／發呆／工作中，並依狀態偏好安排座位。
- 成員造型：依使用者編號自動產生的像素角色。
- 成員面板：顯示所選成員當日的工時清單（唯讀）。

不在第二階段：自訂造型、拖曳換位子、走路動畫、超過 16 人、在大廳替別人記工時、週曆／月曆。

## 2. 使用情境與限制

- 沿用第一階段：單人、本機執行，伺服器只綁定 `127.0.0.1`，以使用者自己的 API token 讀取。
- 大廳只讀取 OpenProject，**不新增任何寫入**。`server/openproject/client.mjs` 的寫入白名單不變。
- 能看到哪些成員的工時，取決於該 token 在 OpenProject 的權限。
- 示例模式同樣可用，提供假成員與假工時。

### 2.1 已實測的 OpenProject 行為（2026-11-16、11-17，唯讀）

| 用途 | 請求 | 結果 |
|---|---|---|
| 列出全部使用者 | `GET /api/v3/users` | 403，不可用 |
| 依名稱搜尋使用者 | `GET /api/v3/principals`，篩選 `name` `~` 加 `type` `=` `User` | 可用；中文、英文皆可 |
| 同上，篩選 `any_name_attribute` | | 500，不可用 |
| 讀取單一使用者 | `GET /api/v3/users/{id}` | 可用，回傳 `id`、`name`、`avatar` |
| 多位成員某日工時 | `GET /api/v3/time_entries`，篩選 `user` `=` `[id…]` 加 `spentOn` `=d` | 可用，一次查詢取回全部 |
| 請假 work package | `GET /api/v3/work_packages/200` | 名稱「請假」，專案 Software Operations |

因為無法列出全部使用者，加入成員只能「輸入名稱搜尋」，不提供瀏覽名單。

## 3. 畫面

### 3.1 頁籤

- 頂部列加上兩個頁籤：「任務欄」「公會大廳」。
- 每次載入頁面都預設在「任務欄」，不記憶上次停留的頁籤。
- 日期列（◀ 日期 ▶ 今天）兩個頁籤共用同一個日期。
- 「任務欄」的內容與行為和第一階段完全相同。

### 3.2 大廳版面

左側是場景，右側是羊皮紙面板（與任務欄的「本日已接任務」同位置、同寬度）。窄螢幕時改為單欄，場景在上、面板在下，場景依寬度等比縮小，不出現水平捲軸。

場景固定有 16 個位子：

| 區域 | 家具 | 位子數 |
|---|---|---|
| 吧檯 | 一座吧檯與酒架 | 5 |
| 工作桌 | 四人桌、雙人桌、單人桌 | 4＋2＋1＝7 |
| 沙發 | 三人沙發、單人沙發 | 3＋1＝4 |

- 有人的位子顯示像素角色、頭上的狀態圖示、腳下的名字（過長時截斷）。
- 沒人的位子只顯示空的家具，不可點選。
- 點角色會選取該成員，角色加上醒目外框，右側面板顯示其內容；再點一次或按面板的「返回」取消選取。
- 角色是按鈕，可用鍵盤聚焦與啟動，無障礙名稱為「{名字}：{狀態}」。

### 3.3 右側面板

沒有選取成員時：

- 標題「公會成員 n / 16」。
- 成員名單：每列顯示小頭像、名字、狀態、當日合計時數；點列等同點場景中的角色。
- 「＋ 招募成員」按鈕；滿 16 人時停用並顯示「大廳已滿」。
- 「重新整理」按鈕與上次更新時間。
- 沒有任何成員時顯示提示「大廳還沒有成員，先招募幾位吧」。

選取成員時：

- 名字、狀態、所選日期。
- 該日每筆工時：work package 編號與名稱、時數、活動、備註。唯讀，沒有 [改]／[刪]。
- 當日合計時數。
- 「請離大廳」按鈕（確認後移除）與「返回」按鈕。

### 3.4 招募成員視窗

做法比照「釘上常駐任務」視窗：

- 輸入名稱搜尋（至少 1 個字，輸入後延遲送出），列出最多 10 位使用者。
- 已在大廳的使用者仍會列出，但標示「已在大廳」且不可選。
- 選一位後按「加入大廳」；成功後關閉視窗並重新讀取大廳狀態。
- 搜尋結果按鈕一律 `type="button"`（第一階段踩過的坑）。

## 4. 狀態與座位

### 4.1 狀態判定

對每位成員，以所選日期的工時判定，依序：

1. 有任一筆工時的 work package 是請假（預設 #200）→ **休息**
2. 沒有任何工時 → **發呆**
3. 其餘 → **工作中**

請半天假又記了其他工時的成員，依規則 1 顯示休息。請假的 work package 編號由設定 `leaveWorkPackageId` 決定，預設 200。

狀態由伺服器判定後回傳，前端不重複判斷。

### 4.2 座位分配

狀態跟著角色走；區域只是偏好，不限定狀態。因為成員上限等於位子數，每位成員一定有位子。

- 偏好順序：
  - 休息：沙發 → 吧檯 → 工作桌
  - 工作中：工作桌 → 吧檯 → 沙發
  - 發呆：吧檯 → 沙發 → 工作桌
- 分配順序：先排休息的成員，再排工作中，最後排發呆。同狀態內依加入大廳的先後。
- 每位成員拿到偏好順序中第一個還有空位的區域，並坐該區編號最小的空位。

分配是純函式：輸入（成員清單與各自狀態）相同時，輸出一定相同，所以資料沒變時角色不會換位子。

### 4.3 造型

- 由使用者編號經固定的雜湊，選出髮型、髮色、膚色、衣服顏色、頭飾，組成 12×16 的像素格，以 SVG `<rect>` 繪製。
- 不存檔、不可調整；同一編號永遠得到同一造型。
- 顏色以 SVG 的 `fill` 屬性指定，不使用 inline style（CSP）。
- 狀態圖示：工作中、發呆、休息各一個像素圖示，顯示在角色頭上；另以文字出現在面板與無障礙名稱中，不單靠圖示或顏色傳達。

## 5. 後端

### 5.1 設定

`config/local.json` 新增選填欄位 `leaveWorkPackageId`（正整數，預設 200）。`GET /api/config` 不需要回傳它。

### 5.2 成員名單儲存

新模組 `server/hall.mjs`，做法比照 `server/quests.mjs`：

- 檔案：即時模式 `data/hall.json`，示例模式 `data/demo-hall.json`。
- 內容：依加入順序排列的 `{ userId, name }` 陣列。
- 操作：`list()`、`add({ userId, name })`（已存在則更新名稱、不重複；已滿 16 位則拒絕）、`remove(userId)`。
- 寫入採「寫暫存檔後改名」，與 quests 相同。

### 5.3 來源介面新增

`server/time-tracking.mjs`（真實）與 `server/demo.mjs`（示例）各新增三個方法：

| 方法 | 真實來源的做法 | 回傳 |
|---|---|---|
| `searchUsers(term)` | `GET /api/v3/principals?pageSize=10`，篩選 `name` `~` term、`type` `=` `User` | `[{ id, name }]` |
| `getUser(id)` | `GET /api/v3/users/{id}` | `{ id, name }` |
| `listEntriesForUsers(date, userIds)` | `GET /api/v3/time_entries`（`getAll` 取完所有頁），篩選 `user` `=` ids、`spentOn` `=d` date，依 id 排序 | `[{ userId, …與 listEntries 相同的欄位 }]` |

`userIds` 為空時不發請求，直接回傳空陣列。工時的 `userId` 取自 `_links.user.href`。

### 5.4 本機 API

| 方法與路徑 | 說明 |
|---|---|
| `GET /api/users/search?q=` | 搜尋使用者，回傳 `[{ id, name }]` |
| `GET /api/hall?date=YYYY-MM-DD` | 回傳大廳狀態（見下） |
| `POST /api/hall/members`，本體 `{ userId }` | 以 `getUser` 確認存在並取得名稱後加入；回傳更新後的成員名單 |
| `DELETE /api/hall/members/{userId}` | 移除；回傳更新後的成員名單 |

`GET /api/hall` 的回應：

```json
{
  "date": "2026-11-17",
  "members": [
    {
      "userId": 18,
      "name": "…",
      "status": "working",
      "totalHours": 3,
      "entries": [
        { "id": 2759, "workPackageId": 202, "workPackageSubject": "支援任務",
          "hours": 1, "activityName": null, "comment": "…" }
      ]
    }
  ]
}
```

- `status` 為 `resting`、`idle`、`working` 之一。
- `members` 依加入順序；座位由前端依 4.2 計算。
- 狀態判定放在獨立的純函式模組 `server/hall-status.mjs`。
- 新的寫入路徑（POST、DELETE）套用第一階段全部防護：`X-Quest-Board: 1`、Origin 白名單、JSON 本體與大小上限。所有路徑同樣受 Host 檢查與 `Sec-Fetch-Site` 檢查。
- 輸入驗證放在 `server/validate.mjs`：`userId` 必須是正整數；搜尋字串沿用 `parseSearchTerm`。

### 5.5 錯誤對應

| 情況 | 本機回應 |
|---|---|
| 加入時大廳已滿 | 409，`hall_full` |
| 加入的使用者不存在或無權讀取 | 404，`not_found` |
| `userId` 格式錯誤 | 400，指出欄位 |
| OpenProject 連線失敗、逾時、5xx | 沿用第一階段的錯誤代碼 |

位子的座標用 CSS 類別（`seat-bar-1` … `seat-sofa-4`）定義，不用 inline style。

### 6.2 讀取與更新

- 進入大廳頁籤、切換日期、按「重新整理」、加入或移除成員後：讀取 `GET /api/hall`。
- 停在大廳頁籤時，每 5 分鐘自動讀取一次；離開頁籤或頁面被隱藏時停止，回來時立即讀取一次。
- 同時只保留最新一次讀取的結果：較舊的請求晚回來時直接丟棄。
- 切換日期時先清空場景並顯示「讀取中…」，避免在新日期下顯示舊日期的狀態。
- 同一天的重新讀取（自動或手動）失敗時，保留現有畫面，並在面板顯示「更新失敗」與上次成功更新的時間。
- 第一次讀取或切換日期後的讀取失敗時，場景保持空白並顯示錯誤訊息。
- 選取中的成員在重新讀取後仍保持選取；若該成員已被移除則取消選取。

## 7. 示例模式

- `server/demo.mjs` 內建約 8 位假使用者可供搜尋，並預先放 5 位進大廳。
- 假工時涵蓋三種狀態：有人請假（#200）、有人沒有工時、有人有一般工時。
- 示例使用者本人在任務欄新增的工時，也會反映在大廳（若本人在大廳中）。
